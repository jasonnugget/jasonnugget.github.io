intro/background

So Chipotle pretty often gives out free entree codes. These codes can be found during streams, important sporting events, or random celebrations. How it works essentially is you text the number 888-222 with whatever phrase they tell you to text and the first amount of people that text it get a free entree that you can use at Chipotle.

The image shows how it works, but if you text the number and before they cap it off, you are given a code you can use on the app or in store. You can find free discord servers that track when codes drop that automatically redirect you to iMessages and autofill out the text but now isn't the time to get into this. Well, this is it right? We got a free code and get to eat for free now! This is amazing already!

There is actually a way where you can get even more free food from just one free entree code. Yes, there was a way to get more free food on top of free food. Previously, there was a way for people to use one entree code to get multiple up to even 10 free bowls at once.

How did it work? First, you had to download the chipotle app. Second, you build your bowl like normally and selecting only one entree. After you add it to cart, everyone would add the same promo code at once. Afterwards, Chipotle's checkout was just holding down a button when the item was free. What everyone had to do was time holding down the button so that everyone checks out at the same time. There you go, you and all your friends got free Chipotle bowls from one entree.

This was previously of course, so it means that it was patched. Well, not entirely. So how the flow of ordering chipotle works is that you have to select a location before going to your cart. Before, you could checkout as many bowls as you want to one location, but now you could only apply the promo code if it was not used at the location already. Meaning that for it to work now, you have to choose different stores. So it still works, but slightly inconvenient if you live in a small city.

the idea

Well, the little "exploit" still worked so what did I do? Obviously I tried to monopolize off of this. Since the flow now was that it had to be at different locations, what I did instead was thinking of a way to automate this process. No one wants to pay full price for a Chipotle bowl, so what did I do? I sold them for $4 each. Since selling it online gave a wide variety of locations, I would be able to efficiently use each entree code since I was no longer limited by store locations.

what i built

So now, it was off to automating this process. What I did originally was try and use playwright, puppeteer, and other browser automations. Well, let's just say this didn't even get close to working when I did this. Why? Because of Kasada antibot. Kasada antibot will be one of the biggest challenges we face all throughout this project (will elaborate more further). Then, after sometime I came across SeleniumBase which patched a lot of ways that these automation browsers left that allowed it to be detected (shoutout UC mode). This was one of the biggest stepping stones.

Afterwards, it was just inspecting the website, finding selectors, and scraping menu items and selections. From this, I was able to build a complete checkout flow. After the checkout flow was built, I had to now open multiple browsers and do these all at once. This is where concurrency comes into play. I also had to use ISP proxies so I would not get rate limited and handling of proxy lists so that they would not be reused. And it worked as shown below...

Now we were smooth sailing. Afterwards, I built a website using React as the frontend and Supabase for the backend (discord login and authentication and database). I did manual balance top ups with crypto through Discord. I got a full stack project working with real paying customers!

everything good comes to an end

Well, I accomplished a few of my goals with this project. First, I wanted to build a project with real users. I accomplished this, maybe at a smaller scale, but I was able to get some where. Second, I built a full stack project that was not for nothing. I learned the most from this project how time consuming real user projects are, scaling issues, and sustainability. This is what brought me to shut down Chippy.

I realized with a small userbase, it was decent, but the project could not scale without servers and a full time commitment to this "business". The scaling of issues came from Kasada. So Kasada looks at your hardware by canvas fingerprinting which I thought I could bypass with small changes in every one of my browsers during the checkout flow but it does not work like that.

I even tried a harder approach which was attempting a fully request based checkout flow, but Kasada antibot was way above my paygrade. This is what initially piqued my interest in learning about reverse engineering websites to understand request flows, javascript executions, and antibot operations. Very quickly I learned how difficult it was to scale this project. I had to use multiple codes a day and Kasada would rate limit my home computer after 2-3 checkout sessions of multiple orders. It was very difficult to bypass these hardware fingerprinting restrictions.

the end

As a result, after the entree codes that I got from the World Cup expired, I shutdown Chippy. I learned a lot and also ate a lot of Chipotle. This was one of the best projects I ever worked on where I could consider myself as beginning to learn as it introduced me into a field of interest where I am naturally curious and something is always going on. It is a constant cat and mouse game in the world of automation and scraping against antibots, where I quickly learned the best developers are the ones that can learn to reverse engineer. I still have the checkout automation process which I plan to open source in the future for others to use!
